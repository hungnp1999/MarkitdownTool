# Ways to Contribute

You can contribute by:

- Reporting bugs
- Suggesting new features
- Improving documentation
- Improving user experience
- Optimizing performance
- Submitting pull requests
- Sharing real-world use cases

---

# Before Creating an Issue

Please:

1. Check existing Issues.
2. Check Discussions.
3. Verify you are using the latest supported version.

---

# Bug Reports

When reporting a bug, please include:

- Operating System
- MarkItDownTool version
- Steps to reproduce
- Expected behavior
- Actual behavior
- Screenshots (if applicable)
- Error messages or logs

---

# Feature Requests

When suggesting a feature, please explain:

- The problem you are trying to solve
- Your proposed solution
- Expected benefits
- Alternative solutions you considered

---

# Pull Requests

Before submitting a Pull Request:

- Ensure the code functions correctly.
- Keep changes focused and easy to review.
- Update documentation when necessary.
- Follow existing coding conventions.

Large changes should be discussed first through Issues or Discussions.

---

# Code Style

General guidelines:

- Write readable code.
- Use meaningful variable names.
- Add comments when necessary.
- Avoid unnecessary complexity.
- Maintain compatibility with supported Python versions.

---

# Community Standards

Please follow:

- CODE_OF_CONDUCT.md
- SECURITY.md
- LICENSE

Respectful and constructive collaboration is expected from all participants.
