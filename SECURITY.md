# Security Policy

## Supported Versions

The following table describes which versions of MarkItDownTool currently receive security and maintenance updates.

| Version | Supported |
| ------- | --------- |
| 3.1.x   | ✅ |
| 3.0.x   | ✅ |
| < 3.0   | ❌ |

Only the latest stable versions are actively maintained.

Users are strongly encouraged to upgrade to the most recent supported release to receive security fixes, dependency updates, and bug fixes.

---

## Reporting a Vulnerability

If you discover a security vulnerability in MarkItDownTool, please report it responsibly.

### Preferred Contact Method

Email:

**nguyenphuhung1999@gmail.com**

### Please Include

When reporting a vulnerability, provide as much information as possible:

- A clear description of the issue.
- Steps to reproduce the vulnerability.
- Affected version(s).
- Screenshots, logs, or proof-of-concept examples (if applicable).
- Potential impact assessment.

### Response Timeline

The project maintainer will make reasonable efforts to:

- Acknowledge receipt of a vulnerability report within **7 days**.
- Investigate and assess reported vulnerabilities.
- Provide status updates when appropriate.
- Develop and release security fixes when feasible.

Response times may vary because MarkItDownTool is an independently maintained personal project.

---

## Responsible Disclosure

Please do not publicly disclose security vulnerabilities before the issue has been reviewed and addressed.

Responsible disclosure helps protect users and gives the maintainer time to investigate and release a fix.

---

## Scope

Security reports are primarily intended for vulnerabilities that could:

- Lead to arbitrary code execution.
- Cause unauthorized file access.
- Allow privilege escalation.
- Expose sensitive user data.
- Circumvent application security controls.
- Compromise the software supply chain.

Examples of issues that are generally not considered security vulnerabilities include:

- Feature requests.
- User interface improvements.
- Documentation errors.
- Non-security-related bugs.

Such issues should be reported through GitHub Issues or Discussions.

---

## Third-Party Components

MarkItDownTool relies on third-party open-source software and libraries.

Security issues originating in third-party dependencies may need to be reported to the maintainers of those projects as well.

Examples include:

- Microsoft MarkItDown
- OCRmyPDF
- Tesseract OCR
- Other Python package dependencies
